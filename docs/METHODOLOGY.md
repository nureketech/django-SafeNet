# Әдістеме

SafeNet KZ әлеуметтік желілердегі контенттен күмәнді схемалардың **белгілерін** табады:

- ақылы ұтыстар (лотереялар);
- онлайн-казиноның жасырын жарнамасы;
- қаржы пирамидалары.

Жүйе әр жазбаға үш нәрсе береді:

- тәуекел ұпайын (0–100) және деңгейін: төмен, орташа немесе жоғары;
- іске қосылған белгілерді, әрқайсысына дәлел-фрагмент;
- шешім қабылдау үшін маманның тексеруі қажет екені туралы ескертуді.

> **Негізгі қағида: үкім емес, белгілер.** Жүйе ешкімге айып таныстырмайды. Ол «тексеруге не жіберу керек және
> неге» деген сұраққа жауап береді. Соңғы шешім — аналитиктікі.

Бұл құжаттағы кестелер `config/signals.yaml`, `config/scoring.yaml` және `models/thresholds.json` файлдарынан
`python -m safenet.docs` арқылы жасалады. Тест олардың сәйкестігін тексереді.

## 1. Деректер

- **Синтетикалық датасет** (`make data`, `data/synthetic/`): 2400 жазба, 430 шаблон.
  - Тілдер: орыс, қазақ, аралас тіл және транслит.
  - Дереккөздер: пост, чат хабарламасы, эфир транскрипциясы, профиль сипаттамасы, скриншот (130 PNG).
  - Бүркемелеу: гомоглифтер («к@зинo»), бос орындар («Л о т е р е я»), эмодзи, сленг.
- **Қиын негативтер** — схемаға ұқсайтын, бірақ схема емес мәтіндер. Мысалдар: тегін розыгрыштар, банк
  депозиттері, турнирлер, мемлекеттік лотерея, дүкен акциялары, схемалар туралы ескертулер.
- **Бөліністерде ағып кету жоқ.** Әр фраза нұсқасы «тұқымға» жатады (нұсқа индексі % 5):
  - 0–2 тұқымдар → train;
  - 3 → val;
  - 4 → test.

  Сондықтан test-тің шаблондары мен тұжырымдары оқытуда кездеспейді.
- **Gold-жинақ** (`data/gold/gold_source.yaml`): қолмен жазылған 122 хабарлама. Ол тек соңғы бағалауда
  қолданылады. Белгілер сөздігі, модель мен шектер gold немесе test бойынша бапталмайды.
- **Барлық деректер ойдан шығарылған:**
  - карта нөмірлері Лун тексерісінен өтпейді;
  - домендер тек `.test` / `.example`;
  - адамдар тек никнейммен аталады;
  - казино мен жобалардың атаулары ойдан шығарылған.
- **Ендірілген желілер:** 10 жасырын желі (ортақ карта, телефон, промокод, домен, сілтеме). Сонымен қатар
  ортақ сайты бар 2 заңды дүкен «тұзақ» ретінде қосылған.

## 2. Өңдеу тізбегі

```
мәтін / скриншот / эфир транскрипциясы
   │  OCR (скриншот болса): Tesseract rus+kaz+eng, алдын ала өңдеу, сенімділік бойынша сүзу
   ▼
нормализация — тіл, бүркемелеуді ашу, қазақ әріптерін бүктеу, нысандар (сома, %, карта, телефон, сілтеме…)
   ▼
белгілер детекторы — regex/сөздік ережелері + есептелетін белгілер, әр белгіге дәлел-фрагмент (span)
   ▼
ML-классификатор — TF-IDF (символдар + сөздер) + белгілер-фичалар → P(lottery / casino / pyramid / none)
   ▼
скоринг — салмақтар + үйлесімдер + ML − төмендететін факторлар + желі бонусы → ұпай, деңгей, түсіндірме
   ▼
байланыстар графы — ортақ реквизиттер арқылы кластерлер; кластер тәуекелі жоғары болса бонус (≤ 10)
```

### 2.1. Нормализация

Нормализация (`safenet.preprocess.normalize`) мына әрекеттерді жасайды:

- тілді анықтайды: `ru`, `kk`, `mixed`, `translit`;
- гомоглифтерді (латын/кирилл) және әріп арасындағы бос орындарды қалпына келтіреді;
- транслитті кириллицаға аударады;
- қазақ әріптерін орыс әріптеріне «бүктейді» (`folded` өрісі). Бір ереже екі тілде де жұмыс істейді, ал
  ұзындық сақталады, сондықтан дәлел түпнұсқа мәтінде дәл бөлектеледі;
- нысандарды бөліп алады:
  - сомалар («5к», «10 000 тг», «5 мың теңге»), пайыздар мерзімімен, көбейткіштер («х2»);
  - Kaspi, карта (маскаланғанын қоса), телефон;
  - сілтемелер, домендер, қысқартқыштар, реферал параметрлер, промокодтар.

### 2.2. Белгілер сөздігі

Әр белгінің сипаттамасы `config/signals.yaml` файлында:

- трек, салмақ, «негізгі» белгісі;
- орыс және қазақ кілт сөздері, regex үлгілері;
- контекст-ерекшеліктер (мысалы, «бесплатно», «турнир», «годовых»);
- нысандар (мысалы, сома сөзге 32 таңбадан жақын тұруы керек).

Екі белгі **есептеледі**:

- `P_UNREAL_RETURN`: сома мен мерзімнен айлық табыс шығарылады, ≥ 30% болса белгі іске қосылады;
- `N_BANK_RATE`: жылдық ≤ 20% болса банктік ставка деп танылады.

Төмендететін (теріс) белгілер ұпайды азайтады. Олар тегін қатысуды, ескертуді, сауданы, банк ставкасын,
шеберлік жарысын және мемлекеттік лотереяны білдіреді.

### 2.4. ML-классификатор

- Фичалар:
  - TF-IDF символдық n-граммдар (2–5, `char_wb`) — бүркемелеуге төзімді;
  - сөздік n-граммдар (1–2);
  - 2.2-бөлімдегі сандық белгілер: жалаушалар, есептелген табыс, нысандар саны.
- Модель: `LogisticRegression` (softmax, `class_weight="balanced"`) + сигмоидалық калибрлеу.
  Калибрлеу бөліністері шаблон бойынша жасалады (GroupKFold).
- `C` гиперпараметрі val бойынша таңдалды. Есеп: [`reports/model_report.md`](../reports/model_report.md).
- ML ұпайдың тек бір бөлігін береді (≤ 40). Ол «жоғары» деңгейді жалғыз өзі бере алмайды (4-бөлімді қараңыз).

## 3. Тәуекел формуласы

```
rule_score  = min(Σ оң белгілердің салмағы + Σ үйлесім бонустары, rule_cap)
ml_score    = ml_weight × P(ең ықтимал трек ≠ none)
negative    = Σ төмендететін белгілердің салмағы
risk_score  = clip(rule_score + ml_score − negative + network_bonus, 0, 100)
```

Шектегіштер:

- **негізгі белгі жоқ** болса, `risk_score ≤ no_core_cap`. Яғни «жоғары» деңгей үшін негізгі белгі міндетті;
- **дәлелі бар оң белгі жоқ** болса, ұпай `medium` шегінен төмен қалады. ML-дің жалғыз өзі жазбаны тексеруге
  жібермейді.

Әр құрамдас бөлік нәтижеде бөлек көрсетіледі. Олардың қосындысы ұпайға тең, бұл кейс карточкасындағы көлденең
диаграмма.

Желі бонусы тек өз ұпайы ≥ `medium` жазбаға беріледі. Шарттар:

- кластерде ≥ 2 аккаунт бар;
- аккаунттарды ортақ карта, телефон, промокод, сілтеме немесе домен байланыстырады;
- кластердің «жоғары» жазбаларының үлесі ≥ 0.5.

Бонус = `network_max × кластер тәуекелі`.

<!-- auto:scoring -->
| параметр | мәні | мағынасы |
|---|---:|---|
| `rule_cap` | 60 | ережелер бөлігінің жоғарғы шегі |
| `ml_weight` | 40 | ML ықтималдығының салмағы |
| `network_max` | 10 | желі бонусының жоғарғы шегі |
| `no_core_cap` | 45 | негізгі белгі болмаса ұпайдың жоғарғы шегі |
| `require_evidence_for_medium` | true | дәлелсіз жазба `medium`-ға жетпейді |
<!-- /auto:scoring -->

## 4. Шектер және оларды таңдау

Деңгейлер:

- `low`: ұпай < medium;
- `medium` («тексеруді қажет етеді»): medium ≤ ұпай < high;
- `high` («басым тәртіппен тексеру»): ұпай ≥ high.

Шектерді `python -m safenet.scoring.tune` (`make train` ішінде) **тек val** бойынша таңдайды:

<!-- auto:thresholds -->
- **medium = 14**, **high = 62** (таңдалған жинақ: `val`).
- medium шарттары: precision ≥ 0.85, қиын негативтердегі FPR ≤ 0.1; осы шартта recall барынша жоғары. Іздеу аралығы 10–64.
- high шарттары: `no_core_cap` (45)-тен жоғары, «high» precision ≥ 0.95, эталон деңгейлермен келісім барынша жоғары. Іздеу аралығы 46–95.
- val-дағы нәтиже: precision 1.000, recall 1.000, қиын негативтердегі FPR 0.0%.
<!-- /auto:thresholds -->

Шектер `models/thresholds.json`-да сақталады. Таңдау кестелері:
[`reports/thresholds.md`](../reports/thresholds.md).

## 5. Скриншоттар мен эфирлер

- **Скриншот** OCR арқылы оқылады. Алдын ала өңдеу: масштабтау, сұр реңк, түстерді аудару, бинаризация.
  Сенімділігі < 30 сөздер алынып тасталады. Латын бренд сөздеріндегі жиі қателер түзетіледі
  («Каврі» → Kaspi).
- Мәтін мен скриншот бірге келсе, екеуінің белгілері біріктіріледі. Дәлелде дереккөз көрсетіледі:
  `text`, `ocr` немесе `transcript`.
- **Эфирлер** транскрипция мәтіні ретінде өңделеді (`stream_transcript`). Бейне мен аудионы тану әзірге
  жоқ (ROADMAP).

## 6. Түсіндірмелер

Әр нәтижеде мыналар бар:

- қазақ және орыс тіліндегі қысқа түсіндірме: белгілер, үйлесімдер, ең ықтимал трек, модель ықтималдығы,
  байланыстар және деңгей;
- әр белгінің дәлелі (`start`/`end` позициялары). Дашборд оларды мәтінде трек түсімен бөлектейді;
- ұпайдың құрамдас бөліктері;
- маскаланған нысандар;
- ескерту.

Бағалау кезінде түсіндірмелердің сапасы да тексеріледі. Дұрыс табылған схемалардың 100%-ында іске қосылған
белгілердің кемінде біреуі эталонмен сәйкес келеді
([`reports/metrics.md`](../reports/metrics.md), «Түсіндірмелер сапасы»).

## 7. Жалған іске қосылулармен жұмыс

Жалған іске қосылу аналитиктің уақытын жейді және адал қолданушыларға зиян келтіруі мүмкін. Сондықтан
жүйеде бірнеше қорғаныс деңгейі бар:

1. **Төмендететін белгілер** (`N_*`) ұпайды азайтады. Бұған тегін қатысу, ескерту/жаңалық, сауда, банк
   ставкасы, турнир және мемлекеттік лотерея жатады.
2. **Контекст-ерекшеліктер.** Мысалы, «слот» сөзі казино контекстінде ақылы ұтыс белгісін іске қоспайды.
3. **Дәлел талабы және негізгі белгі шегі.** ML-дің жалғыз өзі `medium` бермейді. Негізгі белгісіз `high`
   болмайды.
4. **Қиын негативтер** деректе әдейі көп. FPR олар бойынша бөлек өлшенеді. medium шегін таңдағанда шарт —
   қиын негативтердегі FPR ≤ 10%.
5. **Қателерді талдау.**
   - `reports/errors.md` әр FP/FN себебін автоматты түрде көрсетеді.
   - Сөздік тек train/val қателері бойынша түзетіледі, test пен gold қолданылмайды.
   - 8-кезеңдегі түзетулер `PROGRESS.md`-де сипатталған.
6. **Аналитиктің кері байланысы.**
   - «Расталды / Жалған іске қосылу / Өткізіп жіберу» батырмалары шешімді `data/feedback/feedback.csv`-ге жазады.
   - Пилотта бұл деректер сөздік пен модельді қайта оқытуға және шектерді қайта таңдауға қолданылады (ROADMAP).
   - Қайта оқытудың алдында бөлек бақылау жинағы ұсталады.

## 9. Шектеулер

- **Синтетикалық деректер.**
  - test жинағы бөлек фраза тұқымынан, бірақ генератор мен сөздікті бір автор жазған. Сондықтан test-те
    ережелер оптимистік нәтиже береді.
  - Gold (122 хабарлама) авторға «соқыр» жинақ, бірақ ол шағын.
  - Нақты деректердегі сапа пилотта өлшенуі керек.
- **Төлем түбіртектері.** «Kaspi аударым … за слот №37» сияқты, ақылы қатысу сөзі жоқ түбіртек тек әлсіз
  белгі береді, сондықтан өткізіп алынады (errors.md). OCR де латын сөздерін бұзуы мүмкін: «Kaspi» → «Казр!»,
  «₸» → «T». Демодағы түбіртек осы себепті `medium` алады.
- **medium шегі төмен (14).** Бір ғана негізгі белгі (мысалы, «рандомайзер», салмағы 15) тегін қатысу
  белгісінсіз `medium` береді. Бұл «тексеруді қажет етеді» дегенді білдіреді, бірақ аналитикке жүктеме
  қосады.
- **Аралас тілді анықтау** дәлдігі 72.8% ([`reports/preprocess_report.md`](../reports/preprocess_report.md)).
  Белгілер мен модель бүктелген мәтінде жұмыс істейтіндіктен, бұл анықтауға аз әсер етеді.
- **Бейне мен аудио жоқ.** Эфирлер тек дайын транскрипция арқылы өңделеді.
- **Сөздікке тәуелділік.** Жаңа сленг пен жаңа схема түрлері сөздікті жаңартуды талап етеді. ML мен
  аналитиктің кері байланысы бұл тәуелділікті азайтады, бірақ толық жоймайды.

## 10. Этика және деректерді қорғау

- **Үкім емес, белгілер.**
  - Интерфейс пен API нәтижелерінде айыптау мағынасындағы сөздер қолданылмайды. Тізім
    `safenet.common.FORBIDDEN_WORDS`-та, ал тесттер оларды барлық бетте, API жауаптарында және түсіндірмелерде
    тексереді.
  - Әр нәтижеде қазақ және орыс тілінде ескерту бар: «Ықтимал бұзушылықтың белгілері анықталды. ҚР
    заңнамасын ескере отырып, маманның тексеруі қажет.»
- **Түсіндірілетін шешім.** Әр деңгейдің артында нақты белгілер мен мәтіннен алынған дәлелдер тұрады.
  Аналитик олардың әрқайсысын көре алады.
- **Жеке деректерді азайту.**
  - Карта мен телефон графта тек SHA-256 хэш, ал интерфейсте тек маска түрінде сақталады.
  - Тесттер беттерде ашық нөмірлердің жоқтығын тексереді.
  - Аккаунттар идентификатормен белгіленеді.
- **Адамның шешімі.** Жүйе кезекті басымдық бойынша реттейді, бірақ ешқандай автоматты шара қолданбайды.
  Аналитиктің шешімі мен түсініктемесі жазылады.
- **Ашықтық.**
  - Метрикалар, абляция, қателер мен шектеулер ашық жарияланады.
  - Шектерді таңдау тәсілі де құжатталған.
  - Gold пен test баптауға қолданылмайды.
