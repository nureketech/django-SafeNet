# Өнімділік және масштабтау бағасы

`python -m safenet.eval.bench` арқылы жасалды. Уақыттар машинаға тәуелді, үлестер — тұрақты.
Машина: Windows 11, AMD64 Family 23 Model 104 Stepping 1, AuthenticAMD, 12 логикалық ядро, Python 3.14.7; бір процесс, бір ағын.

## Бір жазбаның өңделу уақыты (test, 456 мәтін, 3 өлшеудің ең жақсысы)

| кезең | мс / жазба |
|---|---:|
| ережелер: нормализация + белгілер (regex) | 2.62 |
| ML: TF-IDF + белгі-фичалар + LogReg (батч) | 2.89 |
| толық талдау: ережелер + ML + скоринг + граф | 5.68 |
| OCR (tesseract, 10 скриншот) | 367 |

## Каскадтың бірінші сатысы: «кемінде бір оң белгі»

Арзан қадам тек regex-белгілерді тексереді. Ешбір оң белгі іске қоспаған жазба ML мен OCR-ға жіберілмейді.

| көрсеткіш | мәні |
|---|---:|
| test жазбалары | 482 |
| келесі сатыға жіберілгені (test) | 72.8% |
| схемалардың жіберілгені (каскад recall, 288 схема) | 100.0% |
| `none` жазбаларының сүзілгені (194) | 67.5% |
| — қарапайым `none` | 96.4% |
| — қиын негативтер (110) | 45.5% |

test-те схемалар үлесі жоғары, ал қиын негативтер әдейі схемаға ұқсатып жазылған. Сондықтан нақты ағында сүзілетін үлес жоғарыдағы `none` бағасынан төмен болмайды деп күтеміз.

## Сыйымдылық мысалы

Болжамдар (өлшем емес): тәулігіне 10 000 000 жазба, шың = орташадан ×3, схемалар үлесі 2%, скриншоттар үлесі 10%.

- Шыңдағы ағын: **347 жазба/с**; каскадтан кейін ML-ға **33.8%** жіберіледі.

| саты | қажет CPU ядролары (шыңда) |
|---|---:|
| ережелер (барлық ағын) | 0.9 |
| ML (тек жіберілгені) | 0.3 |
| OCR (барлық скриншот) | 12.8 |
| салыстыру: каскадсыз толық талдау | 2.0 |

Ядролар саны = шыңдағы ағын × бір жазбаның уақыты. Бұл — бір ағынды Python өлшемі бойынша консервативті баға: батчтау мен векторлау оны азайтады.
